# AI Review Agent

AI Review Agent — это ИИ-агент для автоматического анализа кода в Pull Request с использованием Google Gemini.

## Описание проекта

Данный агент автоматически запускается при создании или обновлении Pull Request в GitHub-репозитории. Он получает изменения в коде, анализирует их с помощью модели Google Gemini и формирует рекомендации по улучшению.

## Возможности

- автоматический запуск через GitHub Actions;
- анализ изменений в Pull Request;
- генерация рекомендаций по улучшению кода;
- помощь в поиске потенциальных ошибок;
- интеграция с GitHub-репозиторием;
- использование Google Gemini API для анализа кода;
- ручное управление агентом с помощью команд в комментариях Pull Request.

## Настройка

Для работы агента необходимо добавить API-ключ Gemini в секреты GitHub-репозитория.

Перейдите в настройки репозитория:

```text
Settings → Secrets and variables → Actions → New repository secret
```

Добавьте секрет:

```text
GEMINI_API_KEY
```

## Запуск

Агент запускается автоматически при создании или обновлении Pull Request.

Пример события для запуска workflow:

```yaml
on:
  pull_request:
    types: [opened, synchronize, reopened]
```

## Управление агентом

| Команда | Описание |
|---|---|
| `/agent review` | Запускает анализ изменений в Pull Request. Агент проверяет код, ищет возможные ошибки и формирует рекомендации. |
| `/agent explain` | Объясняет внесённые изменения простым языком. Команда используется для получения краткого описания того, что было изменено в Pull Request. |
| `/agent fix` | Запускает исправление найденных проблем в коде и предлагает решение не применяя их к Pull Request. |
| `/agent auto-fix` | Запускает автоматическое исправление проблем, применяя их в Pull Request. |
| `/agent revert-last-fix` | Откатывает последние изменения, внесённые ИИ-агентом. |

## Ограничение при работе с fork-репозиториями

> [!NOTE]
> При создании Pull Request из fork-репозитория GitHub Actions по соображениям безопасности не передаёт пользовательские secrets в workflow.

Из-за этого агент может не выполнить анализ кода для Pull Request, созданного из fork-репозитория, так как у него не будет доступа к `GEMINI_API_KEY`.

Также в Pull Request из fork-репозитория токен `GITHUB_TOKEN` может иметь только права на чтение, поэтому публикация комментариев в Pull Request может быть ограничена.
